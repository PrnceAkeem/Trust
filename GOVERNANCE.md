# Governance

Trust currently uses a maintainer-led governance model.

## Roles

- **Contributors** propose research, documentation, designs, tests, or code.
- **Reviewers** provide domain or technical review without merge authority.
- **Maintainers** triage work, accept decisions, merge changes, publish releases,
  and enforce community and security policies.

The initial project founder acts as the first maintainer. Maintainer identities
and a succession process must be recorded before the first public release.

## Decision Process

Routine changes are decided through pull-request review. Material decisions
affecting architecture, security, protocols, storage, deployment, compatibility,
licensing, or governance require an ADR and a reasonable public review period.

Maintainers seek consensus, but may make a documented final decision when
consensus is not possible. Security response may be handled privately until
coordinated disclosure is safe.

## Transparency

Accepted decisions, release criteria, and roadmap changes should be recorded in
the repository. Conflicts of interest that could materially affect a decision
should be disclosed.

## Evolution

Governance should expand as sustained contributors emerge. Changes to this file
require a pull request and an ADR explaining the reason and transition.
